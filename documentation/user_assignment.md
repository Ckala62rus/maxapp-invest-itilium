# Задание (личное напоминание)

Кратко, что ты взял на себя и что стоит не забыть.

## 1. Создание заявки — реальная интеграция с ITILIUM

Цель: чтобы кнопка «Создать заявку» в мини-приложении создавала заявку в 1С, а не только в демо-контуре.

- В проекте уже есть цепочка: UI → Vuex `createTicket` → `POST /api/v1/tickets` → `TicketService` → `internal/api/itilium_client.go` (`CreateTicket`).
- Сейчас клиент шлёт JSON на путь вроде `{baseURL}/tickets`. В legacy это должно маппиться на **`create_sc`** (и отдельно маркетинг — **`create_sc_Marketing`**, когда договоритесь о контракте). См. таблицу в `documentation/itilium_api.md`.
- Твоя работа по аналогии с **`RegisterUser`** / **`find_employee`**: уточнить у 1С URL, метод (часто form POST), имена полей; реализовать в `itilium_client.go`; разобрать ответ в `models.TicketDetail`.
- Учти: тип заявки на фронте (`requestType`) — ИТ / маркетинг / DAX; вложения сейчас — только **имена файлов**, не бинарная загрузка, пока отдельно не оговорено.

## 2. Локальная разработка в браузере (без MAX)

- В `frontend/.env.local`: `VITE_DEV_BACKEND_PROXY_TARGET` на свой backend, при необходимости **`VITE_DEBUG_USER_ID`** (например известный id в ITILIUM).
- Перезапуск Vite после изменения `.env.local`.
- На проде не оставлять отладочные заголовки идентичности без необходимости (`AUTH_ALLOW_DEBUG_IDENTITY_HEADERS` и т.п. — см. `.env.example`).

## 3. Проверка через реальный MAX

- После модерации бота: HTTPS-туннель, реальный `initData`, проверка `POST /api/v1/auth/max/validate` и дальнейших запросов с bearer-токеном.

## 4. Коммиты

- Делать **небольшие тематические** коммиты с сообщениями **на русском**, один смысл — один коммит; пушить на remote по мере готовности (как в правилах проекта).
